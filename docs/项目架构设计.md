# ClassNest 项目架构设计

> 依据：`docs/tech.md`《WakeUp 风格课程表桌面替代品 · Vibe Coding 开发总规格》
>
> 项目定位：使用 **Vue 3 + Vite + TypeScript + Pinia + Vue Router + Naive UI + SCSS + Tauri 2 + SQLite** 构建的本地优先桌面课程表应用。
>
> 明确不做：闹钟、上课提醒、系统通知、后台提醒任务、倒计时、铃声、手机端 Widget、教务系统自动登录。

---

## 1. 架构概述

ClassNest 采用**本地优先、分层清晰、领域逻辑与 UI 完全隔离**的单体桌面应用架构：

- 前端承担绝大部分业务逻辑与 UI；
- SQLite 是唯一数据持久化层；
- Tauri（Rust）只承担真正需要原生能力的工作（文件系统、备份、系统信息、窗口/托盘）；
- 核心课表领域逻辑（周数、日期、冲突、位置）全部收敛到 `src/engine/`，不进入 Vue 组件与 CSS。

```text
┌──────────────────────────────────────────────┐
│                  Vue 3 UI                     │
│  Views → Components（Naive UI + 自定义 Grid） │
└───────────────────────┬──────────────────────┘
                        │
┌───────────────────────▼──────────────────────┐
│              Pinia Stores                     │
│   schedule / course / settings / ui           │
└───────────────────────┬──────────────────────┘
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌───────────────┐             ┌──────────────────┐
│  src/engine/  │             │  Repositories    │
│  纯领域逻辑    │             │  唯一 DB 访问口  │
└───────────────┘             └────────┬─────────┘
                                       ▼
                     ┌───────────────────────────┐
                     │ SQLite（@tauri-apps/plugin-sql）│
                     │  migrations / 本地文件库    │
                     └───────────────────────────┘
```

**数据单向流动原则：**

```text
SQLite
  ↓
Repository
  ↓
Pinia Store（唯一状态事实来源）
  ↓
Engine 计算 RenderedCourse
  ↓
UI（View / Component）
```

禁止反向依赖：Component 不得直接 `db.select(...)`，Pinia 不得跳过 Repository，Engine 不得依赖 Vue。

## 2. 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| UI 框架 | Vue 3 + `<script setup lang="ts">` | 统一 Composition API |
| 构建 | Vite | |
| 语言 | TypeScript | |
| 状态管理 | Pinia | 四个 Store |
| 路由 | Vue Router | 8 个业务路由 |
| 组件库 | Naive UI | 管理型 UI 默认组件库 |
| 样式 | SCSS | 主课表自定义样式 |
| 桌面容器 | Tauri 2 | `src-tauri/` |
| 数据访问 | `@tauri-apps/plugin-sql` | SQLite CRUD 由前端 Repository 完成 |
| 数据库 | SQLite | 单文件 + 迁移脚本 |
| 测试 | 单元测试为主 | Engine / Repository / Importer |

**UI 框架规则：**

- 管理型界面（设置、表单、弹窗、导入预览、错误提示）优先使用 Naive UI；
- 主课表 Schedule Grid **禁止**使用 `NDataTable` / `<table>`，必须使用 CSS Grid + absolute positioning + Vue 组件；
- 主课表属于领域 UI，不强行塞入通用表格组件。

## 3. 分层架构

### 3.1 View 层（`src/views/`）

每个 View 只做页面级组合、路由入口和少量生命周期编排，不写数据库、不写领域算法。

```text
views/
├── ScheduleView.vue            # / 主课表
├── ScheduleManagerView.vue     # /schedules 多课表管理
├── CourseEditorView.vue        # /course/new 与 /course/:id/edit
├── ScheduleSettingsView.vue    # /schedule/:id/settings
├── ImportView.vue              # /import
├── ExportView.vue              # /export
└── GlobalSettingsView.vue      # /settings
```

### 3.2 Component 层（`src/components/`）

组件按领域分组，只消费 Store / Engine 输出，不持有重复数据副本。

```text
components/
├── schedule/       # 自定义课表组件（唯一允许实现 Grid 的领域 UI）
├── course/         # 课程详情 / 编辑 / 时间段编辑
├── schedule/       # 课表切换器 / 课表管理 / 新建课表
├── settings/       # 课表设置 / 外观设置 / 时间表编辑 / 全局设置
├── import/         # 导入流程组件
└── common/         # AppHeader / EmptyState / ConfirmDialog / LoadingState
```

### 3.3 Store 层（`src/stores/`）

| Store | 职责 |
| --- | --- |
| `schedule.ts` | 课表列表、activeScheduleId、加载/切换/创建/删除/更新 |
| `course.ts` | 当前课表课程、加载/新增/编辑/删除/刷新 |
| `settings.ts` | 全局设置、课表外观（ScheduleStyle）、主题、语言 |
| `ui.ts` | Drawer / Modal / 当前周 / 导入弹窗 / 导出弹窗 等 UI 状态 |

**状态原则**：同一数据只允许一个事实来源，禁止 CourseCard / ScheduleGrid / Store 各存一份副本。

### 3.4 Repository 层（`src/repositories/`）

所有数据库操作必须经过 Repository，View 与 Component 禁止直接访问 SQLite。

```text
repositories/
├── ScheduleRepository.ts
├── CourseRepository.ts
├── CourseSessionRepository.ts
├── ScheduleStyleRepository.ts
└── SettingsRepository.ts
```

每个 Repository 提供 `findBy...` / `findById` / `create` / `update` / `delete` 等成组方法，返回 TypeScript 模型，不向调用方暴露 SQL。

### 3.5 Engine 层（`src/engine/`）

项目最重要的模块，必须独立于 Vue 与 UI。

```text
engine/
├── scheduleEngine.ts    # 统一输出 RenderedCourse[]
├── weekEngine.ts
├── dateEngine.ts        # getDateOfWeek / getCurrentWeek
├── conflictEngine.ts    # detectConflicts
├── positionEngine.ts    # top / height / left / width
└── weekRuleEngine.ts    # isWeekMatched / getMatchedWeeks
```

核心输出：

```ts
interface RenderedCourse {
  courseId: number;
  sessionId: number;
  name: string;
  weekday: number;
  startSection: number;
  endSection: number;
  startTime: string;
  endTime: string;
  teacher?: string;
  location?: string;
  weekMatched: boolean;
  conflict: boolean;
  conflictCourseIds: number[];
  opacity: number;
  top: number;
  height: number;
}
```

UI 只消费 `RenderedCourse`：

```text
Pinia
  ↓
ScheduleEngine
  ↓
RenderedCourse[]
  ↓
ScheduleGrid
```

### 3.6 导入导出层（`src/importers/`、`src/exporters/`）

导入必须遵循统一管线，解析结果不能直接写库：

```text
File / Input
  ↓
ImporterRegistry
  ↓
Importer
  ↓
ImportedSchedule（统一模型）
  ↓
Validation（校验 + 冲突检测）
  ↓
Preview（课程数 / 时间段数 / 异常数 / 冲突数）
  ↓
用户确认
  ↓
Commit → SQLite
```

Importer 统一接口：

```ts
interface CourseImporter {
  id: string;
  name: string;
  canHandle(input: ImportInput): Promise<boolean>;
  parse(input: ImportInput): Promise<ImportedSchedule>;
}
```

导出支持 CSV（当前/全部课表）、ICS（不含 VALARM）、JSON 完整备份。

### 3.7 Service 层（`src/services/`）

```text
services/
├── backupService.ts     # 完整/部分备份与恢复（事务、回滚）
├── fileService.ts       # 文件读写（经 Tauri 原生命令）
└── settingsService.ts
```

### 3.8 数据访问层（`src/database/`）

```text
database/
├── connection.ts        # SQLite 连接（@tauri-apps/plugin-sql）
├── database.ts          # 打开时执行迁移
└── migrations/
    ├── 0001_initial.sql
    ├── 0002_course_override.sql
    ├── 0003_schedule_style.sql
    └── 0004_app_settings.sql
```

所有数据库变化必须通过新增 migration（`0005_xxx.sql`），禁止修改旧 migration；删除关系必须使用 `ON DELETE CASCADE`，连接开启 `PRAGMA foreign_keys = ON;`。

## 4. Tauri（Rust）边界

```text
src-tauri/
├── src/
│   ├── main.rs
│   ├── lib.rs
│   └── commands/
│       ├── file.rs       # 文件系统能力
│       ├── backup.rs     # 备份文件读写
│       └── system.rs     # 系统信息 / 原生窗口 / 托盘
├── migrations/
├── capabilities/
└── tauri.conf.json
```

原则：

- SQLite CRUD 尽量由前端 Repository + `@tauri-apps/plugin-sql` 完成；
- Rust command 只承担真正的原生能力（文件系统、系统信息、备份、原生窗口、托盘）；
- 不为普通数据库 CRUD 创建大量 Rust command。

## 5. 核心流程设计

### 5.1 主课表渲染流程

1. 启动 → `scheduleStore.loadSchedules()` 读取课表；
2. 无课表：展示空状态（NEmpty +「创建课表 / 导入课表」，不得白屏）；
3. 有课表：一次性加载课程与时间段 → Pinia 缓存；
4. 切换周：不重新查询 SQLite，由引擎基于缓存重新计算；
5. `ScheduleEngine` 合成周匹配、冲突、位置、透明度 → `RenderedCourse[]`；
6. `ScheduleGrid`（CSS Grid + absolute）渲染课程卡。

### 5.2 新建课表流程

创建课表的同一流程内必须完成三件事：

```text
schedule（课表基本信息）
  + 默认 timetable（时间表）
  + 默认 schedule_style（外观）
```

### 5.3 调课流程（CourseOverride）

```text
原课程
  +
CourseOverride（move / cancel / replace）
  =
最终课程
```

只影响指定日期，不修改原课程；下一周原课程保持原安排。

### 5.4 备份 / 恢复流程

备份：完整 JSON，必须包含 `version` / `exportedAt` 与各表数据：

```json
{
  "version": 1,
  "exportedAt": "...",
  "schedules": [],
  "courses": [],
  "courseSessions": [],
  "courseOverrides": [],
  "timetables": [],
  "scheduleStyles": []
}
```

恢复：验证版本 → 验证结构 → 检查引用关系 → 预览 → 用户确认 → 事务写入，失败必须回滚。

## 6. 数据模型（领域对象）

```text
Schedule 1 ──< Course 1 ──< CourseSession
    │                     └──< CourseOverride（按 schedule + session + date）
    ├──< ScheduleStyle（1:1）
    └──> TimeTable 1 ──< TimeSection

AppSetting（全局：theme / language / activeScheduleId / autoBackup / startupBehavior）
```

要点：

- Course 不保存星期、节次、老师、地点，这些属于 CourseSession；
- 一门课程允许多个 Session；
- WeekRule 以 JSON 结构化保存（`type: range | odd | even | custom`，禁止 UI 直操作字符串）；
- ScheduleStyle 属于课表而非全局配置；
- 冲突不删除后者，必须保留两个课程并做冲突布局。

## 7. UI 骨架与交互约束

主界面：

```text
ScheduleView
├── ScheduleHeader（课表名称 / 当前周 / 当前日期范围 / 新增 / 导入 / 导出 / 更多）
├── WeekNavigator（上一周 / 下一周 / 今天 / 输入周数 / 当前周高亮）
├── ScheduleGrid
│   ├── TimeAxis
│   ├── WeekHeader
│   ├── DayColumn × 7
│   └── CourseCard
└── MorePanel
```

交互约束：

| 场景 | 组件 |
| --- | --- |
| 危险操作确认 | NDialog |
| 状态提示 | NMessage / NNotification / NAlert |
| 表单 | NForm + NFormItem |
| 课程详情 | NDrawer（不使用路由） |
| 设置页 | NTabs（基本设置 / 时间表 / 外观 / 高级） |
| 空状态 | NEmpty + NButton |
| 数据库错误 | NNotification |
| 导入错误 | NAlert + ImportErrorList |
| 不可恢复错误 | Error Boundary，不得出现 Uncaught Promise 导致页面崩溃 |

保存策略（统一）：普通字段用保存按钮，外观设置实时保存。

---

## 8. 性能与持久化原则

- 课程数据加载一次 → Pinia 缓存 → Engine 计算；切周不重新查库；
- 仅在课程/课表/设置发生修改后刷新数据；
- 不因每次鼠标移动执行 `SELECT * FROM course`；
- 所有数据变更落 SQLite，重启后数据保留；
- 日志：开发阶段 `console.debug/warn/error`，正式版统一 `logger.debug/info/warn/error`。

| 主题 | 用例 |

## 10. 与需求边界的关系

**真正需要高度还原的是产品语义**：课表模型、周数、时间段、冲突、多课表、外观、导入导出。

**不是**：页面数量、按钮数量、移动端功能、WakeUp 代码结构。

最终产品是：本地优先、桌面原生体验、无提醒负担、数据结构严谨、支持复杂课表规则的 WakeUp 风格课程表。
